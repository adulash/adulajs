Field options: required, unique (partial, active rows), sortable, searchable (generated tsvector), filterable, permissionLevel, sequence, column, default (create prefill, server default and column default), visibleWhen ({ sibling: value | values }; hidden fields are stored empty and not required), min / max (length, numeric limit or count), pattern (anchored RegExp source), format (string: email, url or phone), precision / scale (decimal, percent), options (enum, multiSelect), resource / table (manyToMany).

Resource options: scoped (required), scope.from (the unit follows a required belongsTo parent), title (fields that name the record in relations, pickers, tasks and approvals), submittable (docStatus, submit/cancel/amend-by-copy), version (optimistic locking, default with submittable), unique (composite combinations of fields, partial over active rows), list / form / show / serialize / hidden, actions, hooks.beforeSave / hooks.afterSave, validator / model (optional: without validator a VineJS validator is derived from the fields).

Role rule conditions: $eq, $ne, $in, $lt, $gt, $like on scalar fields; unsupported conditions are refused. Organization scope is always added with AND. `$actor.id` names the signed-in user on user fields, createdBy and updatedBy ($eq, $ne, $in), bound per request.

Workflow steps: condition, update, notify, approval, decision, delay, http, end. Workflow and step names: use lower-case letters, digits and underscores, starting with a letter (for example release_approval, notify_approved).

## Extension points

- Resource hooks (beforeSave, afterSave) inside the save transaction
- ResourceService.systemSave for module-decided writes (validator, hooks and audit, no role rules); ResourceService.rehome after a parent moves
- Assignment closing notes (Assignments closeNote: optional or required); managed assignments (managed: true) closed by module code with Assignments.close
- Page override: inertia/pages/<resource>/{index,form,show}.tsx replaces the generated page
- Create links with defaults: /resources/<resource>/create?defaults[field]=value
- Domain events <module>.<resource>.{created,updated,deleted,submitted,cancelled,amended} with idempotent listeners
- Module workflows (Module.workflows) with versioned definitions
- Approval delegation while out of office (WorkflowDelegations; never widens record access)
- Step SLA deadlines (sla: hours, dueSoonHours, escalate overdue | notify | reassign, to a recipient or { manager: roleKey }) evaluated by the sla:evaluate job
- Message templates edited per deployment
- Outgoing webhooks and the bearer-token /api/v1 API
- Typed API client of the bearer-token API: GET /api/v1/client.ts per token, or node ace adula:client into clients/<system>/
- Signed inbound webhooks raising inbound.<source>.<event> through the outbox
