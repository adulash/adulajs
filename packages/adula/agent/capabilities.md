# AdulaJS capabilities (2.1.0)

Generated by `node ace adula:capabilities`. Read this before proposing a module; anything not listed here is not provided by AdulaJS.

## Resource definition

| Field type | Storage |
|---|---|
| string | varchar |
| text | text |
| integer | integer |
| money | bigint minor units, decimal string in JSON |
| boolean | boolean |
| date | date (YYYY-MM-DD) |
| datetime | timestamptz |
| json | jsonb |
| attachment | attachments row id; per-field accept/maxSize |
| belongsTo | foreign key, preloaded, restrict on delete |
| user | users foreign key, restrict on delete; choices are active members of the record unit or its ancestors; related as { id, fullName } |
| hasMany | child resource; inline rows saved with the parent |
| lookup | lookups group key |

Field options: required, unique (partial, active rows), sortable, searchable (generated tsvector), filterable, permissionLevel, sequence, column.

Resource options: scoped (required), scope.from (the unit follows a required belongsTo parent), title (fields that name the record in relations, pickers, tasks and approvals), submittable (docStatus, submit/cancel/amend-by-copy), version (optimistic locking, default with submittable), customFields, list / form / show / serialize / hidden, actions, hooks.beforeSave / hooks.afterSave.

Role rule conditions: $eq, $ne, $in, $lt, $gt, $like on scalar fields; unsupported conditions are refused. Organization scope is always added with AND. `$actor.id` names the signed-in user on user fields, createdBy and updatedBy ($eq, $ne, $in), bound per request.

Workflow steps: condition, update, notify, approval, decision, delay, http, end. Workflow and step names: use lower-case letters, digits and underscores, starting with a letter (for example release_approval, notify_approved).

## Extension points

- Resource hooks (beforeSave, afterSave) inside the save transaction
- ResourceService.systemSave for module-decided writes (validator, hooks and audit, no role rules); ResourceService.rehome after a parent moves
- Assignment closing notes (Assignments closeNote: optional or required); managed assignments (managed: true) closed by module code with Assignments.close
- Page override: inertia/pages/<resource>/{index,form,show}.tsx replaces the generated page
- Create links with defaults: /resources/<resource>/create?defaults[field]=value
- Domain events <module>.<resource>.{created,updated,deleted,submitted,cancelled,amended} with idempotent listeners
- Module workflows (Module.workflows) with versioned definitions
- Message templates edited per deployment
- Outgoing webhooks and the bearer-token /api/v1 API
- Signed inbound webhooks raising inbound.<source>.<event> through the outbox

## Outside AdulaJS

- Dynamic fields or a field editor screen
- Runtime plugins
- A visual workflow editor
- Multi-tenant SaaS in one database (one deployment per organization)
- XLSX import until a maintained parser passes the dependency rule (GAP-006)
